# Лабораторная 3 — Файлы и файловые системы

**Курс:** Операционные системы, 01.09.2025–31.12.2025

## Задание

1. Написать программу, копирующую каталог «задом наперёд». Программа получает путь
   к каталогу и создаёт каталог с именем, прочитанным наоборот (для `qwerty` —
   `ytrewq`), затем копирует все регулярные файлы (пропуская файлы других типов),
   переворачивая их имена и содержимое: содержимое копируется с последнего байта
   и до нулевого.
2. Написать программу, которая создаёт, читает, изменяет права доступа и удаляет
   файлы, каталоги, символьные и жёсткие ссылки. Нужное действие определяется
   именем, под которым запущен исполняемый файл — на него создаётся необходимое
   количество жёстких ссылок с именами, соответствующими действиям. Разобраться
   со структурами ядра `dentry`, `inode`, `file`.

   Программа должна уметь: создать / вывести содержимое / удалить каталог;
   создать / вывести / удалить файл; создать символьную ссылку, вывести её
   содержимое, вывести содержимое файла по ссылке, удалить ссылку; создать
   и удалить жёсткую ссылку; вывести права доступа и количество жёстких ссылок;
   изменить права доступа.
3. Изучить назначение `/proc/pid/pagemap` и написать программу, выводящую его
   содержимое в структурированном виде.

## Файлы

## Сборка и запуск

```bash
gcc reverse_directory2.c -o reverse_directory
./reverse_directory ./qwerty        # создаст ./ytrewq

# мультивызов: одна программа, много имён
gcc commands_for_files.c -o program
for name in create_dir list_dir remove_dir create_file read_file remove_file \
            create_symlink read_symlink read_symlink_target remove_symlink \
            create_hardlink remove_hardlink print_file_info change_permissions; do
    ln program "$name"
done

./create_dir mydir
./print_file_info mydir
./remove_dir mydir
```

## Что показывает работа

Ключевой приём второй программы — определение действия через `argv[0]`:
`strrchr(argv[0], '/')` отсекает путь, и дальше `strcmp` по имени выбирает ветку.
Работает это только с **жёсткими** ссылками: все имена указывают на один и тот же
inode, то есть на один физический файл с одним набором прав и одним содержимым,
а различается только dentry — запись в каталоге, через которую файл открыли.
Копия файла дала бы N независимых inode, символьная ссылка подставила бы в
`argv[0]` имя ссылки, но добавила бы лишний уровень разыменования. Именно на этом
различии dentry/inode и построено задание.
