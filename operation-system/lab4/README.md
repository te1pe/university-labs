# Лабораторная 4 — Адресное пространство процесса

**Курс:** Операционные системы, 01.09.2025–31.12.2025

## Задание

### 1. Структура адресного пространства

Программа, создающая переменные разных видов (локальные, статические в функции,
константы в функции, глобальные инициализированные и неинициализированные,
глобальные константы) и выводящая их адреса. Сопоставить адреса с областями из
`/proc/<pid>/maps`, через `nm`/`readelf` определить секции. Написать функцию,
возвращающую адрес локальной переменной, и прокомментировать результат. Написать
функцию, работающую с буфером на куче (выделение, запись, вывод, освобождение,
повторный вывод, смещение указателя, освобождение по смещённому указателю).
Завести переменную окружения, изменить её, проверить значение после завершения.

### 2. Управление адресным пространством

Программа, которая выводит pid, ждёт секунду, делает `exec(2)` самой себя.
Программа, которая наблюдает за ростом стека (рекурсия с массивом на стеке),
за кучей (цикл выделений), присоединяет регион в 10 страниц через `mmap(2)` с
`MAP_ANONYMOUS`, меняет права доступа и проверяет реакцию на их нарушение,
отсоединяет часть страниц.

### 3. Самодельная куча

Реализовать `my_malloc()` / `my_free()` над анонимным регионом, полученным
через `mmap(2)`.

## Сборка и запуск

```bash
gcc main3.c -o main3 && ./main3 &
cat /proc/$!/maps                    # сопоставить адреса с областями

nm main3 | grep -E ' [bBdDrR] '      # секции .bss / .data / .rodata

gcc address_space3_2.c -o as32 && ./as32
watch -n1 cat /proc/$(pgrep as32)/maps
```

## Что показывает работа

Адреса переменных ложатся в разные области `/proc/<pid>/maps` по своей природе:
глобальные инициализированные — в `.data`, неинициализированные — в `.bss`,
константы — в `.rodata` (доступна только на чтение), локальные — на стеке,
выделенные `malloc` — в heap. `mprotect` позволяет увидеть границу между этими
областями руками: после снятия права на запись обращение к региону порождает не
ошибку функции, а сигнал от ядра, потому что нарушение прав ловит MMU при
трансляции адреса, а не код программы.

Отдельный случай разобран в `NOTES.txt`: при возврате адреса локальной переменной
GCC (ругаясь `-Wreturn-local-addr`) подставляет `NULL` вместо настоящего адреса,
и разыменование даёт `SIGSEGV` на нулевой странице — она в Linux принципиально
не отображается именно для того, чтобы ловить разыменование NULL.
