# Лабораторная 6 — Межпроцессное взаимодействие

**Курс:** Операционные системы, 01.09.2025–31.12.2025

## Задание

### 1. Через буфер в разделяемой памяти

Создать буфер размером в страницу через `mmap(2)`, общий для двух процессов.
Писатель непрерывно пишет `unsigned int` от 0 до `UINT_MAX`, по достижении конца
региона начинает с начала. Читатель читает и проверяет последовательность чисел,
при сбое выводит сообщение. Объяснить причину сбоев и предложить решение.

Синхронизировать доступ сигналами: писатель по заполнении буфера сигналит
читателю и ждёт ответного сигнала, читатель по готовности данных читает,
проверяет и сигналит обратно. Оба процесса обрабатывают `SIGINT`: получивший
завершается с сообщением о сигнале, второй — с сообщением о том, что завершение
вызвано остановом другого процесса. При завершении освобождаются все ресурсы.

### 2. Через pipe

Организовать передачу последовательности `unsigned int` через pipe. Объяснить,
почему здесь нет проблем, возникавших с разделяемой памятью. Реализовать функцию,
которая порождает процесс и перенаправляет stdout родителя на stdin потомка.

### 3. Через доменные сокеты

Эхо-сервер на доменном сокете и клиент к нему; проверить работу с несколькими
клиентами одновременно.

## Файлы

| `6_1_6_sync_shm.c` | та же схема с синхронизацией через `SIGUSR1`/`SIGUSR2` и обработкой `SIGINT` |
| `6_2_1_pipe.c` | передача последовательности через pipe |

> Эхо-сервер на доменных сокетах (пункт 3) в работе не реализован.

## Сборка и запуск

```bash
make            # соберёт все четыре программы
./6_1_1_unsync_shm     # видно сообщения о сбоях последовательности
./6_1_6_sync_shm       # сбоев нет, Ctrl+C корректно гасит оба процесса
make clean
```

Сборка идёт с `-Wall -Wextra -O2 -std=c11 -D_POSIX_C_SOURCE=200809L`.

## Что показывает работа

Разделяемая память даёт двум процессам один и тот же кусок физической памяти без
какого-либо арбитража: писатель и читатель работают по нему одновременно, и
читатель регулярно видит частично обновлённую картину — отсюда разрывы в
последовательности. Синхронизация сигналами превращает свободный доступ в
поочерёдный: каждый процесс работает с буфером только получив разрешение.

Pipe такой проблемы не имеет, потому что это не общая память, а очередь в ядре:
данные копируются, чтение и запись сериализуются самим ядром, а запись объёмом
до `PIPE_BUF` атомарна. Цена — лишнее копирование, которого нет у shared memory.
