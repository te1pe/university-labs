# Лабораторная 7 — Понятие пользователя, управление правами

**Курс:** Операционные системы, 01.09.2025–31.12.2025

## Задание

Использование SUID-бита для доступа к файлам:

1. Создать файл с правами «чтение только владельцу».
2. Написать программу, которая выводит содержимое этого файла, а также реальный
   и эффективный идентификаторы пользователя.
3. Запустить программу из-под своего пользователя и из-под чужого.
4. Объяснить результат.
5. Установить SUID-бит.
6. Запустить программу из-под своего пользователя и из-под чужого.
7. Объяснить результат.

## Файлы

| Файл | Что это |
| --- | --- |
| `reader.c` | чтение `secret.txt`, вывод real и effective UID |
| `secret.txt` | файл с правами `600` — чтение только владельцу |

## Запуск

```bash
gcc reader.c -o reader
chmod 400 secret.txt
./reader                       # владелец читает успешно
sudo -u nobody ./reader        # чужой пользователь — Permission denied

sudo chown $USER reader && sudo chmod u+s ./reader
ls -l reader                   # права вида -rwsr-xr-x
sudo -u nobody ./reader        # теперь читается: euid подменился на владельца
```

## Что показывает работа

Права на файл проверяются по **эффективному** идентификатору пользователя, а не
по реальному. Без SUID-бита оба совпадают, и чужой пользователь получает
`Permission denied`. SUID-бит заставляет ядро при `execve` подставить в euid
владельца исполняемого файла — реальный uid остаётся прежним, а проверка доступа
проходит от имени владельца, поэтому файл с правами `600` становится читаемым.
Это же и делает SUID опасным: программа с этим битом выполняет действия с чужими
правами, и любая ошибка в ней превращается в способ обойти права доступа.
