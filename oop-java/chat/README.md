# Чат

Многопользовательский чат с комнатами: регистрация, вход, обмен сообщениями
и файлами, история переписки. Клиент и сервер — в одном проекте, общаются
по WebSocket.

## Стек

- Java 17
- Java-WebSocket 1.5.3 — и сервер, и клиент
- JavaFX 21 — интерфейс клиента
- Gson 2.10 — JSON
- Maven

## Что умеет

| Возможность | Как устроено |
| --- | --- |
| Регистрация и вход | пароль хранится как SHA-256 в `users.json` |
| Комнаты | создание, список, переход между комнатами |
| Сообщения | рассылка всем участникам комнаты |
| Файлы | передаются в base64, складываются в `uploads/` |
| История | последние сообщения комнаты подгружаются при входе, лежат в `history.json` |
| Список участников | обновляется при входе и выходе |

## Запуск

```bash
mvn clean package
```

Три режима — задаются аргументом:

```bash
mvn exec:java -Dexec.mainClass=org.example.Main -Dexec.args="server"   # только сервер
mvn exec:java -Dexec.mainClass=org.example.Main -Dexec.args="client"   # только клиент
mvn exec:java -Dexec.mainClass=org.example.Main                        # оба сразу, локально
```

Без аргумента сервер поднимается в отдельном потоке, через секунду стартует
клиент — так удобнее проверять на одной машине. Порт по умолчанию `8080`.

## Структура

```
org/example/
├── Main.java                  выбор режима: сервер, клиент или оба
├── MessageDTO.java            единый объект сообщения, ходит по сети как JSON
├── server/
│   ├── ChatServer.java        WebSocket-сервер, переопределяет WebSocketServer
│   ├── ChatCommandHandler.java разбор типов сообщений и вся логика ответов
│   ├── UserManager.java       регистрация, вход, хеширование паролей
│   ├── RoomManager.java       комнаты, кто где сидит
│   └── HistoryManager.java    история комнат, запись в JSON
└── client/
    └── ChatClient.java        окно JavaFX и подключение к серверу
```

Клиент и сервер обмениваются одним и тем же `MessageDTO`; поле `type`
(`register`, `login`, `join`, `message`, `file`, `rooms`, `users`, `history`,
`system`) определяет, как его разобрать. Состояние комнат держится
в `ConcurrentHashMap` — к серверу подключается несколько клиентов сразу.

## Ограничения

Учебный проект, в реальную сеть его выпускать не стоит:

- **Без TLS.** Обычный `ws://`, трафик не шифруется — пароль уходит открытым.
- **Хеш без соли.** SHA-256 без соли уязвим к радужным таблицам.
- **Файлы без ограничения размера** — большой файл в base64 нагрузит сервер.
- **Хранилище — JSON-файлы**, не база: параллельная запись не защищена.
