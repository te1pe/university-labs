# Лабораторная 4 — Фильтрация трафика с помощью eBPF

**Курс:** Компьютерные сети, 01.09.2025–31.12.2025

## Задание

Создать eBPF-программу, фильтрующую входящие TCP-пакеты на основе IP-адреса
источника и порта:

- убедиться, что Linux собран с поддержкой eBPF;
- установить `clang`, `llvm`, `bpftool`, `libbpf`;
- реализовать и запустить программу фильтрации;
- запустить `tcpdump` или Wireshark для анализа трафика;
- попробовать установить TCP-соединение с заблокированным IP, убедиться,
  что пакеты отбрасываются;
- проверить, что пакеты с других адресов проходят через фильтр.

Модифицировать программу так, чтобы отбрасывались только TCP-пакеты, секция
данных которых содержит слово `SPAM` в кодировке ASCII.

## Файлы

| Файл | Что делает |
| --- | --- |
| `xdp_ip_port_filter.c` | основной вариант по заданию: DROP при совпадении **IP источника и порта назначения** (`127.0.0.1` + `8080`) |
| `xdp_port_filter.c` | фильтр только по порту, в обе стороны — подробно закомментированная версия с разбором каждого шага |
| `xdp_spam_any_port.c` | DPI: DROP, если в полезной нагрузке TCP встречается `SPAM` |
| `xdp_spam_filter.c` | то же, но только для порта 8080 — закомментированная версия |

## Сборка и запуск

```bash
# сборка в BPF-байткод
clang -O2 -g -target bpf -c xdp_ip_port_filter.c -o filter.o
clang -O2 -g -target bpf -c xdp_spam_any_port.c  -o spam.o

# загрузка на loopback
sudo ip link set dev lo xdpgeneric off 2>/dev/null
sudo ip link set dev lo xdpgeneric obj filter.o sec xdp
ip link show lo                     # видно prog/xdpgeneric id ...

# логи bpf_printk
sudo sh -c 'echo > /sys/kernel/debug/tracing/trace'
sudo cat /sys/kernel/debug/tracing/trace_pipe

# проверка
sudo tcpdump -i lo -nn port 8080
nc -zv 127.0.0.1 8080               # соединение не устанавливается

# снять программу
sudo ip link set dev lo xdpgeneric off
```

Проверка SPAM-фильтра: поднять `nc -l 8080`, подключиться вторым `nc` и отправить
строку со словом `SPAM` — пакет не дойдёт, тогда как строка без него проходит.

## Как устроен разбор пакета

Программа работает на хуке XDP — в самой ранней точке приёма, до выделения
`sk_buff`. На вход приходит `struct xdp_md` с двумя указателями, `data` и
`data_end`, между которыми лежит сырой кадр. Заголовки «накладываются трафаретом»:

```
data → ethhdr → iphdr → tcphdr → payload
                ↑ длина переменная: iph->ihl * 4
```

Перед каждым обращением обязательна проверка `(void *)(hdr + 1) > data_end` —
без неё verifier откажется загружать программу: он должен статически доказать,
что чтение не выйдет за границу пакета. По этой же причине цикл поиска `SPAM`
в payload ограничен константой, а не длиной пакета.

Возврат `XDP_DROP` уничтожает пакет до того, как ядро потратит на него хоть что-то,
`XDP_PASS` пропускает дальше по стеку. Строка `char _license[] SEC("license") = "GPL"`
обязательна: без неё ядро не даст использовать большинство helper-функций,
включая `bpf_printk`.
